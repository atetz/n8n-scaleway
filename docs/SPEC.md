# Spec: n8n on Scaleway

A personal n8n Setup on one Scaleway VM. OpenTofu creates the infrastructure, Ansible provisions the containers. Terms are defined in [GLOSSARY.md](../GLOSSARY.md); the main architectural choice is in [ADR 0001](adr/0001-single-vm-docker-compose.md).

The repository is public. No secret, domain, e-mail address or personal IP range is ever committed.

## Repository layout

```
infrastructure/          OpenTofu (Infrastructure stage)
provisioning/            Ansible (Provisioning stage)
  files/compose/n8n/       operator-supplied compose file, copied as-is
  files/compose/traefik/   operator-supplied compose file, copied as-is
  group_vars/all.yml       Settings (non-secret, committed)
  inventory.ini            generated by OpenTofu, gitignored
.env                     Secrets file, gitignored
.env.example             committed template of the Secrets file
```

`.gitignore` additionally ignores `.DS_Store`, `.env` and `provisioning/inventory.ini`.

## Prerequisites (README)

- A Scaleway project with an SSH key registered in IAM.
- An existing State bucket in the same region as the Setup.
- `scw` CLI configured: the Scaleway provider picks up `~/.config/scw/config.yaml`.
- `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` holding a Scaleway API key, for the S3-compatible state backend. This talks to Scaleway Object Storage; AWS is not involved.
- OpenTofu and Ansible installed locally.

## Infrastructure stage (OpenTofu)

### Backend

- `s3` backend against Scaleway Object Storage, endpoint `https://s3.<region>.scw.cloud`.
- Bucket name comes from a variable; it must be passed at `tofu init` (OpenTofu early evaluation).
- Region is derived from `zone` (e.g. `fr-par-1` → `fr-par`). No separate region variable.
- `use_lockfile = true`, plus the Scaleway compatibility flags (`skip_credentials_validation`, `skip_region_validation`, `skip_requesting_account_id`, path-style addressing).

### Variables

| Variable | Default | Notes |
|---|---|---|
| `state_bucket` | — | Required, used by the backend |
| `project_id` | — | Required |
| `name_prefix` | — | Required, prefixes every resource name |
| `zone` | `fr-par-1` | |
| `image` | `docker` | Scaleway Docker InstantApp label (verified) |
| `instance_type` | `DEV1-M` | |
| `root_volume_size_gb` | `40` | |
| `ssh_key_name` | — | Name of the project's IAM SSH key |
| `ssh_allowlist_ipv4` | — | List of CIDRs |
| `ssh_allowlist_ipv6` | — | List of CIDRs |
| `operator_access_key` | — | Access key ID (not secret) of the key you run OpenTofu with; keeps you in the Backup bucket policy |
| `backup_retention_days` | `30` | Lifecycle expiry on the Backup bucket |

Operator values live in a gitignored `.tfvars` file.

### Resources

- **Flexible IPs**: one `scaleway_instance_ip` of type `routed_ipv4`, one of type `routed_ipv6`, both attached to the instance via `ip_ids`.
- **Security group**: `inbound_default_policy = "drop"`. Accept TCP 80 and 443 from `0.0.0.0/0` and `::/0` (explicit rule per family). Accept TCP 22 from each CIDR in the SSH allowlist. Outbound left open.
- **Instance**: `image`, `instance_type`, root volume of `root_volume_size_gb`, the security group, both IPs, cloud-init user data.
  - `lifecycle { prevent_destroy = true, ignore_changes = [image, user_data] }`, so the VM holding the live database is never replaced by accident.
- **cloud-init** (first boot only):
  - Create the Deploy user `deploy` with the public key from the `scaleway_iam_ssh_key` data source (looked up by `ssh_key_name`).
  - Passwordless `sudo`, member of the `docker` group.
  - `PermitRootLogin no`, `PasswordAuthentication no`.
  - Install and enable `unattended-upgrades`.
- **Backup storage**:
  - Backup bucket with a lifecycle rule that expires objects after `backup_retention_days`, and one that aborts incomplete uploads after 1 day.
  - IAM application for the backup job with an IAM policy of `ObjectStorageObjectsWrite` on the project. Scaleway requires an IAM grant before a bucket policy has any effect.
  - Bucket policy on the Backup bucket: the application may only upload (`PutObject` and multipart parts), never read or delete. Buckets with their own policy, such as the State bucket, stay closed to it. The operator (resolved from `operator_access_key`) keeps full access; without that statement the bucket policy would lock the operator out.
  - `scaleway_iam_api_key` for that application. The secret key is therefore stored in the state; the State bucket must stay private.
- **Inventory**: `local_file` writes `provisioning/inventory.ini` pointing at the IPv4 address, user `deploy`.

### Outputs

- `ipv4_address`, `ipv6_address`
- `backup_access_key`, `backup_secret_key` (sensitive)
- `next_steps`: the A and AAAA records to create, and the reminder to copy the backup key into the Secrets file.

## Manual step between stages

1. Create an A record (IPv4) and an AAAA record (IPv6) for the domain.
2. Copy `tofu output -raw backup_access_key` / `backup_secret_key` into the Secrets file.

Let's Encrypt only succeeds once DNS resolves to the Setup.

## Provisioning stage (Ansible)

One playbook, always connecting as the Deploy user. Steps, in order:

1. `wait_for_connection`, then `cloud-init status --wait`.
2. **Secrets file check**: read the local `.env`; fail with the list of missing keys before changing anything.
3. **Split secrets** onto the VM, each file mode 600:
   - `traefik/.env`: `ACME_EMAIL`
   - `n8n/.env`: `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `N8N_ENCRYPTION_KEY`, `DOMAIN`, `GENERIC_TIMEZONE`, `EDITOR_ALLOWLIST`
   - root-only backup credentials file: backup access key and secret key
4. **Traefik**: copy the compose file unchanged, `docker compose up -d`. This creates the external `proxy` network. Traefik creates `letsencrypt/acme.json` itself.
5. **Postgres**: copy the n8n compose file, start only the `postgres` service and wait for it to be healthy.
6. **Dump import** (only if `dump_file` is set):
   - If the database has no tables: copy the Dump to the VM and run `pg_restore --no-owner --no-privileges -U $POSTGRES_USER -d $POSTGRES_DB` inside the Postgres container.
   - If it has tables: skip with a warning. Re-running provisioning is always safe.
   - Must run before n8n's first start, because n8n creates its tables on startup.
7. **n8n**: start the full n8n compose project.
8. **Backup timer**: a systemd service and timer running daily at the configured time. It streams `docker exec n8n_postgres pg_dump -Fc` through a pinned `rclone/rclone` container into the Backup bucket (no temporary file), with a timestamped object name.

### Implementation notes

- **Reading the Secrets file**: Ansible parses `.env` itself (it is not copied as-is). Skip blank lines, `#` lines, and every `AWS_*` and `TF_VAR_*` key. `TF_VAR_operator_access_key` holds a `$(...)` command that only a shell `source` expands, so it must never be evaluated or copied.
- **Backup upload with a write-only key**: the backup application may only `PutObject` (plus multipart parts). rclone must not list or check the bucket: use `rcat` with `--s3-no-check-bucket` and `--s3-no-head`, provider `Scaleway`, endpoint `s3.<region>.scw.cloud`. Bucket name and region come from `tofu output backup_bucket` / `backup_region`.
- **Unverified until the first real Backup**: that `ObjectStorageObjectsWrite` plus the bucket policy is enough for the upload. If it returns 403, the IAM policy in `infrastructure/backup.tf` needs adjusting.
- **Postgres 18 on a fresh VM**: no data to migrate; only the volume path changes.
- **Test Dump**: the operator has a real Dump from the existing install, kept in `provisioning/dumps/` (gitignored via `*.dump`). Use it for the Dump import acceptance check: workflows present, credentials decrypt with the old `N8N_ENCRYPTION_KEY`.
- **README**: not written yet. Covers both stages; see "README must cover" below. Loading `.env` works either with `set -a; source .env; set +a` or with the oh-my-zsh `dotenv` plugin (which only loads `.env` from the directory you `cd` into).

### Secrets file (`.env`)

One file holds every secret for both stages. OpenTofu gets its keys by loading the file into the shell (`set -a; source .env; set +a`); Ansible ignores the `AWS_*` keys when splitting.

| Key | Notes |
|---|---|
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | Scaleway API key for the State bucket (OpenTofu backend) |
| `TF_VAR_operator_access_key` | Always `$(scw config get access-key)`; `source` runs it, so it matches the key the provider reads from the `scw` config |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | |
| `N8N_ENCRYPTION_KEY` | Always required. Must match the key of any Dump being imported, or saved credentials can't be decrypted |
| `DOMAIN` | Kept out of the repo because it is personal |
| `ACME_EMAIL` | Let's Encrypt account e-mail |
| `GENERIC_TIMEZONE` | |
| `EDITOR_ALLOWLIST` | Comma-separated CIDRs. Use `0.0.0.0/0,::/0` to allow everyone |
| `BACKUP_ACCESS_KEY`, `BACKUP_SECRET_KEY` | From `tofu output` |

### Settings (`provisioning/group_vars/all.yml`)

- Remote directory for the compose projects.
- Backup schedule, default `03:00`.
- Backup bucket name and region (or read from OpenTofu output).
- Pinned `rclone/rclone` image tag.
- `dump_file`: empty by default, set with `-e dump_file=path/to/file.dump`.

## Changes to the supplied compose files

- **Postgres**: `postgres:18` pinned to an exact minor version; volume changes to `postgres_data:/var/lib/postgresql` (the image's data path changed in 18).
- **Traefik**: pin an exact patch version instead of `v3.7`.
- **Routing**: both routers are always active.
  - `n8n-open`: `Host(${DOMAIN}) && (PathPrefix(/webhook) || PathPrefix(/form))`, priority 100. Covers the `-test` and `-waiting` variants.
  - `n8n-restricted`: `Host(${DOMAIN})`, priority 1, with an `ipallowlist` middleware fed by `EDITOR_ALLOWLIST`.
  - `IP_WHITELIST` is renamed to `EDITOR_ALLOWLIST`.

## Dump format

Custom format (`pg_dump -Fc`), the same format Backups produce. This matches the dumps already made from the existing install:

```
pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc
```

## Out of scope

- n8n queue mode (workers and Redis).
- Multiple environments, workspaces or modules.
- DNS management in OpenTofu.
- Re-applying hardening on an existing VM (cloud-init runs once; rebuild instead).
- Monitoring and alerting.

## README must cover

- Prerequisites above.
- Run order: `tofu init` (with the State bucket) → `tofu apply` → DNS records + copy backup key → `ansible-playbook`.
- `N8N_ENCRYPTION_KEY` is always supplied and must match any imported Dump.
- Dump import usage and the empty-database rule.
- Restoring from a Backup (download from the Backup bucket, then Dump import on a fresh Setup).
- Hardening only happens on first boot.
- The instance is protected by `prevent_destroy`; how to deliberately rebuild.
- The State bucket holds the backup API secret and must stay private.

## Acceptance checks

- `tofu validate` and `tofu plan` succeed with an example `.tfvars`.
- After `tofu apply`, SSH as `deploy` works from an allowlisted address; SSH as `root` is refused; port 22 is unreachable from a non-allowlisted address.
- After provisioning, `https://<domain>` serves n8n with a valid Let's Encrypt certificate, and HTTP redirects to HTTPS.
- With `EDITOR_ALLOWLIST` narrowed, the editor returns 403 from outside the list, while `/webhook/...` and `/form/...` still answer.
- Running the playbook a second time changes nothing and does not re-import a Dump.
- A Dump import from the existing install shows the old workflows, and saved credentials decrypt.
- The backup timer produces an object in the Backup bucket, and that object imports cleanly into a fresh Setup.
